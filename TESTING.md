# Verification performed

Latest round (per-user permissions, Ubuntu 22.04 support, IP addressing, private CA): built and tested on **Ubuntu 24.04 Linux** with the .NET 10.0.402 SDK, real Git, real OpenSSH 9.6 and nginx. Earlier rounds ran on the Windows development PC.

- Release build: **0 warnings, 0 errors** (`TreatWarningsAsErrors`).
- Dependency-free integration/security runner (`scripts/test.ps1` or `dotnet PrivateGit.Tests/bin/Release/net10.0/PrivateGit.Tests.dll`): **165 passing checks** (including dashboard branch deletion: own branches only, admins any, unowned admin-only, main protected, CSRF, stale-page and ref-injection checks).
- SSH permission gate, end to end (`sudo bash scripts/test-ssh-gate.sh /path/to/PrivateGit`, Linux, root): **51 passing checks** (including a simulated *hung* NAS: pushes stay under a second, the server backup stays current, stuck NAS copies never pile up, and the NAS catches up after recovery; the hidden main backup: updated on every main push, snapshots kept, not visible or reachable over SSH by any path, other branches ignored, `MainBackup=false`, NAS copy only for selected repositories, offline NAS and broken backup target never blocking pushes; and creator recording, `git push --delete` of own vs. someone else's vs. unowned branches, admin override, main and tag protection, read users, the missing-hook fail-safe, `AllowBranchDelete=false` and force-push refusal) with a real sshd using the installer's rendered `Match User git` policy, temporary system accounts, real clone/push by four users (write, read, no grant, admin), unlinked legacy keys, per-key `--from` limits, interactive-shell, command-injection, path-traversal and port-forwarding attempts, immediate revocation, and `add-client.sh --list/--revoke`.
- Installer suite (`bash scripts/test-installer.sh`, non-root): **128 passing checks** (including keeping administrator settings across upgrades), covering IP/hostname/CIDR validation, environment/nginx/sshd rendering, private CA generation (IP SAN, reuse on rerun, re-issue on address change, key modes), `nginx -t` on the rendered IP-addressed site with that certificate, and CSR generation for DNS and IP.
- Published self-contained `linux-x64` single file: requires glibc >= 2.27 (Ubuntu 22.04 has 2.35) and no ICU (`InvariantGlobalization`). The SSH gate starts in about 70 ms per connection.
- Browser check (headless Chromium): the admin Access page and a user's filtered repository list render correctly.

Full-installation run (package built on the Windows PC, sandbox without systemd, so a minimal `systemctl` stand-in started the same three programs): `install.sh` with the detected IP, default network and private CA (option 1) completed and passed its health check. HTTPS verified strictly against the generated CA, HTTP redirected, a foreign Host header was dropped, 5080 was loopback-only, the git account ran only the gate, and file modes matched the design. Then `admin.sh` users, `add-client.sh` keys, admin grants through the browser Access tab, and real `git clone`/`push` over port 22 as separate Linux users (write, read, no access, admin). Force-push and branch deletion were refused, revocation was immediate, and users saw only their granted repositories. Rerunning `install.sh` with a newer package (upgrade) kept all users, keys, permissions and repositories.

Backup round, on the installed test server: an upgrade kept a custom setting, created the root:gitrepos 2770 backup folder and backed up existing repositories. A push to main added snapshots and a NAS copy (a local folder stood in for the SMB share; a real CIFS mount was not available in the sandbox). A normal Linux user could not list the backup folder. `backup-restore` of an older snapshot created a new branch without touching main. After the live repository was deleted, `backup-restore` recreated it with the same main commit, default branch, ownership and push guards, read users could clone and write users could push, and backups continued.

NAS-never-blocks round: with the NAS configured but unreachable, the upgrade completed in 8 s and never touched the NAS (server-only backups). `admin.sh backup-now` skipped the NAS after its probe (134 ms) and still made the server backups. `backup-list --nas` reported the NAS as unreachable instead of waiting. A push to main took about 0.5 s with the server backup updated.

Bugs found by that run and fixed:
1. **SSH clone/push of dashboard-created repositories failed with "detected dubious ownership"** (repositories owned by `gitdash`, SSH Git running as `git`; Git's safe.directory check, also in Ubuntu 22.04's patched Git 2.34.1). The gate now marks only the single repository it has just authorized as safe (`git -c safe.directory=<that repo>`). `test-ssh-gate.sh` now creates repositories as a separate dashboard account, as in production, so it catches this (23 checks).
2. **nginx returned 429 Too Many Requests during fast browsing** because both stylesheets counted against the per-client limit. Stylesheets are now exempt and the page burst is 40; the login limit (5/min) is unchanged.
